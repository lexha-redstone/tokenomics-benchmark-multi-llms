This document details the LLM models, their pricing (used for benchmark cost calculation), and the common model combinations (architectures) evaluated in this repository.

## 2. Benchmark Architectures & Model Combinations

We evaluate the following multi-model routing and cascading strategies to find the cost-performance "sweet spot".

### A. Single Model Direct Completion (`single`)
Direct completion using a single model.
- **Example Combinations**:
  - `gemini-3.1-flash-lite` (Ultra-low cost)
  - `gemini-3.5-flash` (Medium cost/performance)
  - `claude-sonnet-5` (Premium capability)

### B. Read-Heavy / Write-Heavy Split (Advisor-Executor) (`read-write`)
Uses a premium advisor model to read the context, plan the logic, and write guidance (< 200 words). A cheaper executor model then writes the code using the guidance.
- **Example Combinations**:
  - **Planner**: `gemini-3.5-flash` / `claude-sonnet-5`
  - **Executor**: `gemini-3.1-flash-lite`

### C. Generation Offload Cascade (`cascade`)
Generates initial code with a cheap model. If tests fail, it escalates code repair to a premium model.
- **Example Combinations**:
  - **Generator**: `gemini-3.1-flash-lite`
  - **Escalation**: `gemini-3.5-flash` (with thinking enabled) or `claude-sonnet-5`

### D. Sweet-Spot Hybrid (`hybrid`)
Combines advisor-executor split with test triage and thinking escalation.
1. **Plan**: `gemini-3.5-flash` (Advisor)
2. **Execute**: `gemini-3.1-flash-lite` (Executor)
3. **Cheap Repair**: `gemini-3.1-flash-lite` (Executor)
4. **Triage**: `gemini-3.1-flash-lite` (Triages unittest error log into a compressed digest)
5. **Escalated Thinking Repair**: `gemini-3.5-flash` (with low thinking budget)

### E. Other Specialized Architectures (mainly Web-Dev)
- **Dynamic Thinking Router (`router`)**: Predicts if the task is `SIMPLE` or `COMPLEX` and routes it to `gemini-3.1-flash-lite` or a thinking `gemini-3.5-flash` advisor split.
- **Dual-Perspective Advisor (`dual-advisor`)**: Two different planners write algorithmic and API contract guidance separately, executor writes the code.
- **TDD Harness (`tdd`)**: Generates edge-case unittests first using a thinking model, then uses them to verify code generated by a cheaper model.
- **Multi-Tier Escalation Shield (`shield`)**: Tiered escalation: Lite -> Flash (Low Thinking) -> Sonnet-5.
- **Peer Reviewer Auditor (`peer-reviewer`)**: Code generated by a premium model is audited by another model, fixed if reviewer finds issues.
